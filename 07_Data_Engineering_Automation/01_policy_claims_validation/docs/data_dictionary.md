# 데이터 사전과 집계 기준

모든 자료는 학습용으로 직접 생성한 가상 데이터입니다. 실제 보험사 자료나 개인 식별정보를 포함하지 않습니다. 기준일은 2026-09-30이며 금액 단위는 원입니다.

## 계약 자료

| 열 | 의미 |
|---|---|
| record_id | 정렬 후에도 원본 행을 식별할 수 있는 고유 번호 |
| policy_id | 계약번호. 원칙적으로 한 계약에 한 행 |
| product | 가상 상품 코드 TERM_A, ACCIDENT_B, HEALTH_C |
| start_date | 보장 시작일. 해당 날짜 포함 |
| end_date | 보장 종료일. 해당 날짜 포함 |

정상 계약의 월말 보유 조건은 `start_date <= 2026-09-30 <= end_date`입니다. 날짜 오류나 누락이 있는 행의 유효 여부는 확인 후 결정합니다. 이번 데이터는 중도 해지와 계약 부활을 포함하지 않습니다.

## 보험금 자료

| 열 | 의미 |
|---|---|
| record_id | 원본 행 고유 번호 |
| claim_id | 보험금번호. 이번 실습에서는 한 보험금에 한 지급 행 |
| policy_id | 계약 자료와 연결하는 계약번호 |
| accident_date | 사고일. 이 날짜로 보장기간을 점검 |
| payment_date | 지급일. 이 날짜로 지급 월을 집계 |
| paid_amount | 지급액. 0은 유효, 공란은 누락, 음수는 확인 필요 |

계약 하나에는 보험금 여러 건이 있을 수 있습니다. 계약번호가 중복된 계약 자료를 보험금에 그대로 결합하면 보험금 행 수와 총액이 증가할 수 있습니다. 연결 건수 0과 2 이상은 검토 대상으로 남깁니다.

9월 지급보험금은 `2026-09-01 <= payment_date < 2026-10-01`에 해당하는 금액입니다. 사고 월과 지급 월은 다를 수 있습니다. 원본의 숫자 지급액 합계와 정제 후 합계의 차이는 제외·수정 내역으로 설명해야 합니다. 보험금 자료와 결합한 행 수를 보유계약 건수로 사용하지 않습니다.

상품별 지급액 집계에 사용할 계약-상품 매핑은 계약번호가 유일하고 연결이 확정된 자료에서 만듭니다. 필요한 값이 없으면 원본 보존 상태에서 확인 필요로 표시합니다.

CSV는 Excel에서 열기 쉽도록 UTF-8 BOM 형식입니다. Excel에서 CSV를 직접 가져올 때는 번호를 텍스트, 날짜를 날짜, 지급액을 숫자로 지정하세요. 제공한 XLSX에는 이 자료형을 적용했습니다.
